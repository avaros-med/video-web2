# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

The video visit room page (video-web2): a React/TypeScript single-page app, forked from Twilio's video app, where a provider and a patient meet for a video visit. Branch `schedule-rewrite` is the build for **ehr** (the Rails service that replaced ark's schedule; ehr `docs/schedule-video.md`): it is served at `/av/video2-mysql/room/{room}` on test and in production, in place of the `schedule-mysql` build. `master` stays ark's page (`/av/video2/room/{room}`), which keeps serving the rooms ark made until those visits are over.

- **The room's ehr comes from the room's name.** ehr names a room `{clinic}_{provider}-{uuid}`; the page calls `https://{clinic}.avaros.ca` in production, `https://{clinic}.test.avaros.ca` on test, `http://localhost:3000` locally (`src/services/http/ehr.ts`). A name with no clinic is not this page's.
- **Anyone with the link joins**; a locked room also asks for its PIN, checked by the page only (`POST …/pin`).
- **The provider is whoever has a valid JWT for the clinic**: the `JWT` cookie OSCAR sets, sent as a bearer token on every call (`authHeaders`). With it ehr answers the provider's name and the visit's patient, marks what they send as the provider's, and opens the side panel's routes. Without it the page is the patient's.
- **No server of its own**: no Express, no Firebase, no token server. The Twilio token, the chat, the files, the side panel and the visit log are all ehr's (`/api/v1/video`).
- **Times are shown in the device's own zone**; ehr answers absolute times.

## Commands

```bash
npm start                # dev server: https://localhost:3003/av/video2-mysql/room/{room} (.env from .env.example)
npm test                 # Jest (ts-jest, jest.config.js); do NOT use react-scripts test
npm run lint             # ESLint on src
npx tsc --noEmit -p .    # type-check src
npm run build            # production build (.env.production)
npm run test:e2e         # Playwright end-to-end suite against a local ehr and OSCAR (below)
```

`npm start` and `npm run build` set `NODE_OPTIONS=--openssl-legacy-provider` (react-scripts 4 on Node 20). `rxjs` is a dev dependency for the pre-commit hook alone: lint-staged 9 (husky) needs an Observable implementation (`any-observable`) and finds none without it.

## Architecture

- `src/services/http/ehr.ts` — the room's ehr address and the provider's JWT.
- `src/services/http/video.service.ts` — every call to ehr: the room, PIN, token, chat line, chat off, file offer and download, chart document offer and opening, removing a participant, the visit log, and the side panel (patient search, chart items, note). Also the chart item's PDF from the EMR's print path (`/oscar/...`, same origin, the provider's EMR session).
- `src/services/events/roomEvents.service.ts` — the room's event stream on ehr (server-sent events: `Message`, `FileOffered`, `DocumentOffered`, `ChatTurnedOff`), one per visit; what a page sends goes to ehr's routes and comes back to every page in the room here.
- `src/hooks/useVideoRoom.ts` — the room read once (`VideoProvider`: `videoRoom`, `videoRoomStatus`, `currentUser` = the signed-in provider).
- `src/hooks/useAvsSocketContext/` — the chat state fed by the stream (the name predates the stream).
- `src/components/EChartPanel/` — the provider's side panel: opens on the visit's patient, search, encounter note, chart documents to send; and the chat (`MessagesView`).
- `src/components/VideoProvider/` — Twilio Video: the room, local tracks, the relay fallback, audio health, diagnostics.
- `public/virtualbackground/` — generated by postinstall from `@twilio/video-processors`.

Chat lines and files go under the sender's Twilio identity (the name typed and a `_123456` suffix ehr adds): unique in the room, it tells a page's own lines from the others'; `displayName` strips the suffix for showing. A file is at most 10 MB and downloaded once within 10 minutes; a chart document is opened once, after the patient types the chart's date of birth.

## Environment

Copy `.env.example` to `.env`. Locally the page runs on https://localhost:3003 (camera and microphone need a secure page), calls ehr at http://localhost:3000 directly (ehr's `CORS_ALLOWED_ORIGINS` has `https://localhost:3003`), and proxies `/oscar` to the local OSCAR (`src/setupProxy.js`) for the chart documents' print paths. `REACT_APP_EHR_URL` points a local page at another ehr; production builds ignore it.

The dev server's own certificate makes Chrome warn ("Your connection is not private"); proceed past it, or give it a trusted one once: `brew install mkcert && mkcert -install && mkdir -p .cert && mkcert -key-file .cert/localhost-key.pem -cert-file .cert/localhost.pem localhost 127.0.0.1`, then `SSL_CRT_FILE=.cert/localhost.pem` and `SSL_KEY_FILE=.cert/localhost-key.pem` in `.env` (`.cert/` is gitignored).

The development build compiles for the same browsers as production (`browserslist`): `@twilio/video-room-monitor` pulls in `@react-spring`, whose code uses optional chaining that react-scripts 4's webpack cannot parse unless Babel compiles it away. After changing `browserslist`, clear `node_modules/.cache`.

For the provider's view locally, sign in to OSCAR (http://localhost:8080/oscar) and copy its `JWT` cookie to path `/` of `localhost` (OSCAR scopes it to `/oscar`), as for the schedule page.

Test and production builds (`.env.production`, gitignored): `PUBLIC_URL=/av/static/video2-mysql`, `REACT_APP_BASE_HREF=/av/video2-mysql`, `REACT_APP_ROOM_TYPE=peer-to-peer`, `REACT_APP_DISABLE_TWILIO_CONVERSATIONS=true`, `REACT_APP_CHAT_DISABLED_BY_DEFAULT=false`, `REACT_APP_ENABLE_BACKGROUND_BLUR=true`. Nothing names ehr: the page works it out.

## Testing

- **Jest** (`src/**/*.test.ts(x)`, enzyme and react-testing-library, `TZ=utc`). ehr's calls are tested against a mocked axios (`video.service.test.ts`), the stream against a fake `EventSource` (`roomEvents.service.test.ts`).
- **End-to-end** (`e2e/`, Playwright): the real page, ehr, OSCAR and the dev clinic; only the Twilio Video SDK and the camera and microphone are mocked (`e2e/fixtures.ts`), the mock room's local participant being the identity ehr put in the token. Each test books its own Video visit through ehr's schedule API (`e2e/support/ehr.ts`) and gives it the Deleted status afterwards; a patient's page has no cookies, a provider's has the signed-in OSCAR cookies the global setup saved. Needs: `npm start`, ehr (`bin/dev`, Twilio Video credentials in its development credentials), OSCAR at http://localhost:8080/oscar, and in `.env.local` (gitignored) `OSCAR_USERNAME`, `OSCAR_PASSWORD`, `OSCAR_PIN` and `E2E_DEMOGRAPHIC_NO` (a test patient on the dev clinic). First time: `npx playwright install chromium`.
